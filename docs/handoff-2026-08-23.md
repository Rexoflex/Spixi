## 6. What this round taught

* ★ **A pass is not a proof.** #503 passed every symptom and still has no evidence, because
  the one row that would have produced it was skipped. Ask for the log, not the tick.
* ★ **A defective brief is the normal case, not the exception.** Two of #506's four premises
  were contradicted by the platform's own documentation, and #149③ was a stale expectation
  reported as a failing test for weeks. Verify the premise; it costs minutes.
* ★ **Mutation is the only thing that finds a vacuous pin.** Five of mine were vacuous on the
  first pass this session. Reading found none of them.
* ★ **A "fix" can trade one defect for another.** 4.1's sheet-above-message ordering solved
  "the menu is covered" by creating "the message is covered".
* ⚠ **Check whether a file exists before `cat >`.** A verdict named only by date collided with
  an existing one from another batch and was overwritten; it was recovered from git, and the
  filenames now carry the batch.
* ⚠ **`EXIT=$?` after a pipe reports the LAST command, not the one you care about.** It
  reported success for a `git add` that had been killed by the bridge's 45-second limit.

`git --no-optional-locks` always. Wipe `obj`/`bin` on any C# change (#387).

⚠ **The device bridge, learned the hard way this session:**

* `tar` needs **`--overwrite`** — the mount cannot unlink to replace.
* `device_bash` is capped at **45 seconds**. A `git add` of 80 files is killed part-way and
  strands `.git/index.lock`. **Stage in chunks of ~20 and verify `diff --cached | wc -l`
  after each.**
* Git write operations strand `*.lock` files the bridge cannot delete — `mv` them into
  `_to_delete/`. They will block GitHub Desktop until moved.
* **`git push` does not work from the bridge** (no credentials, no network). Damir pushes.
* **Never `git add -A`** — the tree carries CRLF-only churn on ~116 files. Stage explicit
  paths and check the staged list against the intended one.
