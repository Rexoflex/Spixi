## 1 · What AND-45 is, in one screen

The nav bar was the last root-coloured band. `MainActivity.InsetsListener` padded the root content view by `max(ime, navBar)`; now it pads **only the keyboard's height above the bar** (`imeLeg = ime > 0 ? max(0, ime − navBar) : 0`), and the nav-bar inset travels exactly as the top one does (AND-7/#401): carrier `*SL{AndroidInsetBottom}` (seeded `"0"` for iOS/Mac/Windows) + a `setInsetBottom` push → `--android-inset-bottom` in every shell head → `base.css` `--safe-bottom: max(env(safe-area-inset-bottom, 0px), var(--android-inset-bottom, 0px))` → the 28 bottom-anchored sites (composer · bottomnav · tray · sheets · toast · scan · lock · launch · call strip · media viewer · the sticky Install bar · chat/home inline · desktop-anchors) read `var(--safe-bottom, 0px)`. A mini-app page keeps native padding `Thickness(0, TopInsetDip, 0, BottomInsetDip)`. `Window.NavigationBarContrastEnforced = false` on API 29+ (else the OS paints its own scrim in 3-button mode).

**The one invariant to hold in your head:** the published value is the NAV-BAR INSET and is **keyboard-independent**. Root + shell = `ime` with the keyboard up, `navBar` with it down; nothing is pushed on a keyboard round. The Opus loop's MAJOR-3 was my first cut publishing an "effective 0 while the keyboard is up" — pushed through the bridge 1–3 frames after the root re-laid out → a one-bar jump of the composer on every open/close. Consequence in chat.html: the Android innerHeight shrink is now `ime − navBar`, so `rememberKbSlot(lastIH − ih + androidInsetBottomPx())` adds the bar back (the tray is the keyboard's FULL height; Session J).
