## Verified clean (things I tried to break and could not)

- **The W-d sheet cannot bypass the native confirm.** Its Confirm emits only the
  pre-existing `ixian:payRequest:<msgId>`; the payload it builds is discarded by the
  shell. `SPayments.handlePayRequest` re-resolves the message, re-parses the amount,
  re-computes the fee, runs `confirmAndAuth` and only then signs. SECURITY.md holds.
- **Amount parity between the sheet and the signature.** The card carries
  `message.message.Trim(':')` (SingleChatPage:2073); C# signs `parseAmount(requestMsg.message)`.
  `money.js toUnits` and `IxiNumber(string)` (Ixian-Core `Utils/IxiNumber.cs`) both
  **truncate** the fraction to 8 places, so no divergence. A trailing-colon amount
  (`"2.5:"`) passes `Trim` on the card but throws in `BigInteger.Parse` → `parseAmount`
  → 0 → `cancel`; it can never sign a different number than it showed. `canSheet`'s
  `/^\d+(\.\d+)?$/` blocks commas, signs and exponents.
- **Fee parity between `handleFeeQuery` (`new ExtendedAddress(addr)`, Primary) and
  `handlePayRequest` (`OfflineTag`).** `prepareTransactionFrom` puts only
  `PaymentAddress` + `Tag` into `toList` and never uses `extendedAddresses` for the fee
  transaction, so the flag does not move the number (only C-3 does).
- **`handleFeeQuery` pushes to the right page** — `SingleChatPage.xaml.cs:171` passes
  `this`, and `setSendQuote` routes compose-first, sheet-second (`chat.html:3966-3970`);
  the two can never be open together.
- **Hardware back knows about the W-d sheet.** It is an `overlay.js` sheet on
  `host: document.body`, the `MutationObserver` on `body[data-overlay-open]` fires
  `syncChatOverlay`, and `chatBack` runs `dismissTopOverlay()` first
  (`chat.html:4304-4306`). `dismissTopOverlay` honours the live `escDismiss:false`
  (`overlay.js:180-183`) — **hardware back cannot dismiss the sheet while money is in
  flight**, it is consumed. Verified against `setOverlayOpts`' live-opts read.
- **W-f end to end when the address DOES match** (jsdom, live component): pick →
  amount seeded from `:send:2.5` → exactly one `feeQuery` for `(address, 2.5)` →
  quote arms Review → the review sheet opens with `2.5 / 0.005 / 2.505`.
- **W-e cap fallback** — `composeSend` is genuinely pushed by `HomePage.xaml.cs:1711`,
  so the hero really does switch; an old exe keeps `ixian:quickscan`. `ixian:sendScan`
  needs no `e.Cancel` of its own (`onNavigating` sets it at :492).
- **W-e vs the RECEIVE takeover** — `quickScanResult` yields the shared slot
  (`home.html:3353`) before mounting the compose. Correct.
- **W-g with the cap absent** — `settings-shell.js:865` gates the whole row on
  `capabilities.paymentAuth && onPaymentAuth`, so nothing renders and the withheld
  `setPaymentAuth` seed is unobserved. `settings.html:788` is the only reader.
  `ixian:paymentAuth:` stays handled (:694) but is unreachable without the row.
- **W-a has no cascade side effects** — every selector in `wallet-send.css` and
  `contact-row.css` is namespaced (`.c-wallet-send*`, `.c-sendreview*`,
  `.c-contact-row*`, plus one `:root[data-desktop]` prefix); nothing can leak into the
  conversation, and the built shell carries the rules (smoke W-a pin).
