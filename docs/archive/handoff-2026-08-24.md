## 2. ★ iOS — the resume point, when Apple lets us back in

Apple's membership lapse invalidated the team profiles (both showed the same
`2026/08/11` expiry). When the renewal is active:

1. Portal → Profiles → **`VS: com.ixilabs.spixi Development`** → Edit → tick the
   certificate and the **iPhone 15** → Generate → Download → double-click to install.
2. Confirm it grants push — the enumeration line must read
   `… :: 3D663HCNTU.com.ixilabs.spixi :: aps=development`.
   `aps=none` means the profile predates the Push tick on the App ID; regenerate AFTER it.
3. `rm -rf Spixi/obj Spixi/bin`, then build with
   `-p:RuntimeIdentifier=ios-arm64 -p:CodesignProvision="VS: com.ixilabs.spixi Development"`.
4. Install, launch. **The phone should now ask for notification permission** — it never
   has. Dev mode → send log → search `[APNSDIAG]`.

| Log line | Meaning | Owner |
|---|---|---|
| `token=… chars` **and** a `subId` | registration works. If push still does not arrive, **#488 is confirmed** | BE dev — a OneSignal dashboard fix |
| `token=(NONE - not registered with APNs)` | the entitlement did not take, or `RequestPermissionAsync` faulted | us |
| no `[APNSDIAG]` at all | `initialize()` never ran — `Node.cs:213` was not reached | us, and it is the #483/B ordering row |

⚠ **A wildcard profile can NEVER carry push.** Apple excludes `aps-environment` from them
because a push entitlement must bind to one app id. Do not try to make the wildcard work.

## 5. ★ What this session taught

* ★ **The push code was never the suspect — it was never asked to run.** Eight batches of
  notification work, and iOS had no entitlement to receive a single push.
* ★ **A fix that is right on one platform can be architecturally wrong on another.**
  #483's Application-registration answer cannot work on iOS, where a killed app runs no
  managed code at all. Porting it would have been a fourth no-op.
* ★ **A build that fails at the gate is the gate working.** codesign refusing an
  entitlement the profile does not grant is the correct outcome, not a defect.
* ★ **Ask what "it works on the old one" actually proves.** Legacy push works — for
  `io.ixian.spixi`. It says nothing about `com.ixilabs.spixi`, and on APNs that is the
  whole question.
* ★ **The device console is the wrong instrument.** `xcrun devicectl device console` does
  not attach reliably, and Ixian `Logging.*` writes to the APP log, not os_log. **Dev mode
  → send log** is the instrument (#321, device-verified this pass).
* ★ **Read the whole method.** `clearRemoteNotifications` has been a no-op on iOS for
  however long, and no test could ever have caught it.
