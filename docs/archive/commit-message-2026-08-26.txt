walk-day batch + triage (#576-#588): elevated picker fallback, headless ring, declined calls, address sheet, phantom overlay, restore contacts, post-wipe stack, mini-app wipe

Eight rows from Damir's walk, built and put through three review rounds. The
loop found 9 MAJORs, two of them reproduced, so several changes below are the
fix of a fix. Verdict: docs/opus-review-verdict-walkday-576.md.

#576 (#568) Windows restore picker. Damir confirmed the exe was launched from an
ELEVATED PowerShell, so the classic cause is confirmed: an administrator process
cannot reach the WinUI picker broker. SFilePicker now falls back to the classic
comdlg32 GetOpenFileNameW, which has no broker. Owner is the MAUI window,
OFN_NOCHANGEDIR keeps the dialog from moving the working directory, the path
buffer is zeroed, a cancel is told apart from a failure by CommDlgExtendedError,
and the elevation state is logged so the branch never has to be asked about
again. The catch is wider than COMException, because a catch narrower than the
failure means the fallback never runs.

#577 (#573) Headless incoming call on Android. The process woke in the
background, MainActivity.Instance was null, and every site on the ring path
threw, so the phone never rang. One helper takes the application context, and it
serves all four reads: the two system services, the ringtone asset, and the
effect probe, whose Activity-gated read also poisoned the missing-asset cache for
the life of the process. The three Activity-only members are null-guarded, and
one of them sits in a finally the catch above does not cover.

#578 (#572 (1)) A hidden request fed the unread badge. FriendMessage sets
read=false for every message, local ones included, and the unread increment is
gated on read alone, so the user's own outgoing request counted one unread
message against them. Fixed at the writer, with a bounded heal for requests
already pending. The heal keys on FriendState.RequestSent and on our own marker
being newest; the second clause is what excludes the mutual-request case.

#579 (#572 (3)) The pressed chat row lifts above the deep scrim on mobile. The
lift goes on the .c-swipe wrapper, the only node the drawer's will-change
stacking context cannot cap. Round 2 reproduced two defects in the first cut: a
row left un-tappable because a deferred undo fired on a node a synchronous
re-render had replaced, and a flush lifting the row of the dying sheet because
querySelector answers in document order. The live lift is module state now,
released synchronously at the action and DOM-wide.

#580 (#572 (4)) A declined call is not a missed call. The decline is written into
the message body so it survives a restart. The marker is "-1" and not a word,
because an older binary parses that body as a duration with a bare Int32.Parse.
The review found the fix inert in the chats list: setLastMessage deep-copies, so
mutating the message reached the log and never the row.

#581 (#569, #570) The tip sheet obeys the truncation canon at the component, for
the title and the avatar disc, and a short bubble gets a measured width floor so
the heart and the Tipped chip stop landing on the timestamp. The floor is
measured through max-content, because the pill row is positioned inside the
bubble and its rendered width is already clamped by it. The other candidate, a
placement flip, oscillates at 60 fps on exactly the bubbles it was written for.

#582 (#575, #572 (2)) The address leaves the Account hero. The chip, the Show QR
row and the What-is-this-address action retire into one row that sits with
Contacts and opens the shared sheet. The sheet gets a smaller QR that still
clears the measured scan floor, near-full height on mobile, an explicit dismiss
control, Share as an icon beside Copy, and a two-column explainer so both
paragraphs share one left edge.

#583 (#574 (1), #565) A queued call request no longer rings as if it were fresh.
The send time reaches the handler, the gate carries a skew margin, a gated call
is announced through the notification gate rather than dropped in silence, and
below the gate the ring budget is shortened by the age already burned. The
restore now reports which way it failed, and the review found the real bug
underneath: writing the zip over the staged envelope destroyed it before the
inner wallet was verified, so one mistyped password made the correct password
fail forever.

Second half, same day: the walk triage (#584-#588).

Damir walked #576-#583 on both platforms — 33 pass, 1 fail, 2 n/a of 36 — and the
walk produced three root causes plus three new bugs. Six are fixed here; the rest is
triaged one-mechanism-per-row in docs/f5-findings-2026-08-26-walkday.md.

#584 The contacts one-shot latch. His [RESTOREDIAG] capture named it:
"friends=0 accFiles=15" — the restored Acc tree on disk with 15 files and the
in-memory list empty. FriendList.loadContacts is guarded by contactsLoaded, a
process-lifetime latch cleared only in FriendList.init, and Node.preStart is its
only caller, so the tree was read once per process launch. Any second account load
in one process kept an empty list. preStart re-arms the latch, but ONLY when the
list is empty: preStart also runs on resume, and an unconditional re-arm rebuilt
every Friend as a new object while an open chat page still held the old one, which
loses an arriving message and drops a typed reply.

#585 Create-after-wipe walked back into the deleted account. goToWelcome popped to
root - which is HomePage - and pushed LaunchPage on top, with a TODO saying the
parent was never removed. Back at the welcome view fell through to base, popped
LaunchPage and revealed the wiped account's home screen, connecting forever. It now
removes every page beneath the new LaunchPage and disposes each one, because a
removed but undisposed page keeps its WebView document live. The back belt swallows
only when a page sits behind this one; gating on "no wallet" alone trapped the user
on the first screen of a fresh install.

#585 rider The wipe leaves mini apps installed. removeAllApps sweeps the apps
directory rather than the in-memory list, because the wipe stops the manager first
and that clears the dictionary - the first cut deleted nothing and looked clean in
the log while every app survived to be re-registered.

#586 A muted contact rang anyway. The push gate worked and only the notification
lane consulted the preferences. A new shouldRingForCall gates the ringtone on the
per-contact mute and the bot flag, deliberately not on the global notifications
master. The ring is also suppressed while our own app lock is up. Only the sound is
gated: the session is created, the timeout still runs, the call stays answerable
from the notification, and the gate fails open.

#588 The first long press after a restore opened the bottom sheet. His log shows the
chats list flushing every two seconds while the block scan runs; renderChatsList
rebuilds every row, so the row captured at pointerdown is detached when the timer
fires and measures zero. Rows carry data-address now and the anchor re-resolves the
live row. A stale rectangle was tried first and rejected: the same flush re-sorts
the list, so it would point the menu at one conversation while acting on another.

An adversarial round over these six found two MAJORs in the fixes themselves - the
unconditional re-arm and the no-op app sweep - plus five MINORs, all corrected here.
