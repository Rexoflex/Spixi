## 3. ★ The big one: notifications when the app is CLOSED

Damir: *"if I close the app the notifications keep coming and they are not grouped, so like
legacy"*, and the global master fails the same way.

`SPushService.initialize()` — which registers the OneSignal `WillDisplay` handler that the
entire NOTIF-5 gate hangs off — runs inside **`Node.start()`**. The closed-app log dates it:

```
19:14:23.73  Starting Spixi
19:14:27.66  Node started        ← ~4 seconds later
```

A push delivered to a killed app is displayed by OneSignal's **native** SDK long before the
.NET handler exists. So the mute, the global master and NOTIF-4's per-chat collapsing all
belong to code that has not run yet — which is also why the rows are ungrouped and look
"legacy". Three notifications split across two chats is precisely what no-grouping looks like.

**The fix, and why it is not in this batch.** The handler has to be registered in the
**Application**, not the Activity and not after node start — a push that wakes a dead process
may never start an Activity at all. That is app-startup ordering surgery, and lifecycle
ordering is the exact class that produced #442, #454 and #460. It gets its own batch and its
own audit rather than being rushed.
