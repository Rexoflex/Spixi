## 3. ★ OPEN #1 — notifications when the app is CLOSED (the biggest one)

Root-caused in **#483**, deliberately not fixed. Read `f5-verdict-2026-08-22b.md` §3.

`SPushService.initialize()` — which registers the OneSignal `WillDisplay` handler that the
whole NOTIF-5 mute gate hangs off — runs inside **`Node.start()`**, about **4 seconds** after
launch. A push to a killed app is displayed by OneSignal's **native** SDK long before the
.NET handler exists, so the mute, the global master and NOTIF-4's collapsing never run.

**The fix:** register the handler in the **Application**, not the Activity and not after node
start — a push that wakes a dead process may never start an Activity at all.

⚠ **This is app-startup ordering surgery, and lifecycle ordering is exactly the class that
produced #442, #454 and #460.** Give it its own batch and its own audit. Check what
`initialize()` actually needs (it wants only `Config.oneSignalAppId`; `setTag` needs the
wallet and must stay where it is).

  hypothesis that was merely reasoned about was wrong.
