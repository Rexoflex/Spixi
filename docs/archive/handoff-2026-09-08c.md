## ★ The one thing to do next: the memory number

Everything else here is small. **§1 of the checklist is the session's point** and it needs the
cable. `[MEMDIAG]` prints `held=` — the app's own count of pages holding a platform WebView,
**the same quantity** `dumpsys meminfo` reports in its footer as `WebViews:`. Two independent
measurements of one number is the discriminator, and it settles the question in one run:

* both climb → a WebView leak, and `skipped=` counts the Dispose calls the guard passed over
* `held=` flat at 3–4 while Native/Graphics climbs → **not** WebViews; stop looking at disposal
* they disagree → the instrument is wrong before the app is; say so, don't act on it

Rule out the heavy seed first. The free discriminator, if it IS WebViews: `CHAT_SPARE_ENABLED = false`.

## ★★ What the memory hunt actually found — and what it did NOT

The suspect was right about the file and wrong about the line. `Dispose()`'s on-stack guard is
**correct** — a covered page must keep its WebView. The defect sits one line above it:

```csharp
public void Dispose()
{
    disposed = true;                                    // ← was here
    if (!Navigation.NavigationStack.Contains(this)) { … teardown … }
```

`disposed` therefore meant *"Dispose() was called"* — and **`OnDisappearing` calls Dispose()
unconditionally, and OnDisappearing fires when a page is merely COVERED.** Nothing ever clears
it: `OnAppearing` does not, and there is no second assignment in the file.

All three readers treat it as *"this page is dead"*, and after a cover none of them is:

| reader | what it does on a live page |
|---|---|
| `popPageAsync` V-5 guard (×2) | returns early — **back stops working** |
| `ContactDetails:293` | drops the deferred `loadMembers` |
| `ContactDetails:375` | drops every roster **chunk** |

Reachable in three taps: HomePage pushes ContactNewPage, a scan page, WalletSentPage and
mini-app pages over itself, and `ContactDetails:817` pushes WalletSentPage over **itself** —
open a contact, tap a transaction, come back, and the member list is guarded out by a page
that is on screen. The assignment moved inside the guard; V-5 is preserved exactly (its repro
is a page that was never pushed, which is off the stack).

⚠⚠ **AND IT IS NOT THE LEAK.** For a covered page the teardown behaviour is byte-identical
before and after — only the flag differs. This fixes three false-dead guards and changes no
memory behaviour. **The 511 MB stays open pending the measurement.** Saying otherwise would
be the exact mistake this project keeps paying for.

English everywhere earns that by a translator writing the English value into the draft, where
the decision travels with the key. `build-locales` contains no skip list at all, and the gate

twelve drafts turns `gif` red.

authority and cannot drift from a re-implementation; `--root` was added so the pin can run it
against a fixture instead of only observing the green outcome (GATE 44's lesson).
