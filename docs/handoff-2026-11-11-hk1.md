## 3b · The flake row `S20G #46 r1 (A-4)`
`scripts/pins-s20g/h-csharp.mjs:213-224` boots the built `dev.html` in jsdom with `wait: 900`, pushes the flags, then sends ONE synchronous click to the S20G switch and expects the verb in the sent list. In the first full run of 2026-11-11 the row and the push were right and only `verb` was false; alone the module is 8 / 8, three times; in the later full runs the row passed. Mechanism read from the code (not reproduced): the bridge's outbox (`src/bridge/native.js:76-88`) sends the FIRST command at once and each later one on its own macrotask, and stays "draining" until a later macrotask finds it empty. The pin waits a fixed 900 ms and checks the sent list in the same tick as its click. A boot-time send that is still draining at that moment (late under load) defers the click's verb by one macrotask — `verb:false` with the switch already flipped, the shape seen. The pin was not changed (another batch's pin). If it fails again in a full run: state the mechanism first, then at most one more run.
