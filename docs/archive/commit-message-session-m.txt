#783 — CHAT APPEARANCE IS THREE CARDS (#774 (7)), AND THE STORAGE DID NOT MOVE.
Background absorbed Opacity (None + the two shipping styles on mobile, + Live flow on
desktop), Canvas became a value row, and the Opacity card is gone from the file rather
than merely unappended. The ruling that made it small: the (style, level) pair stays as
two keys. With Strong retired the level is already binary, so level 0 IS None and
level 1 + style IS that style — the collapse is total, lossless and computable at render
time from the two keys that already exist. Zero migration, zero new spixi.* key, zero
ladder change. Picking None leaves the stored style untouched, so None -> Doodles -> None
-> Matrix never loses the pattern the user had.

#784 — THE APPS TAB OPENS ON GRID AND THE VIEW SURVIVES A RESTART (#775 (8)).
spixi.apps.layout, two fixed words, read at STATE-SEED TIME — inside the appsState
literal, before createAppsList and before any push (#690's three-ladder rule in its
apps-tab form; a late read flips the tab from a column to a 2-up grid in front of the
user). The default moved to grid and a stored 'list' still wins; the order of the two is
asserted, because a default that ran first would be the silent re-skin E1 forbids. The
write takes the value AFTER setAppsLayout normalised it, so the store can only hold one
of the two words. Its security-handover-gate row landed in the SAME batch, per #775's own
process rule.

#785 — THE 120 ms PRESENT HOLD IS A RACE NOW, NOT A WAIT (#766 generalised).
presentPreload awaits Task.WhenAny(Task.Delay(op.revealDelayMs), op.painted.Task). The
timer became a backstop, so this can only ever present EARLIER — a shell that never
signals waits exactly what it waits today, which is why it could be applied to every
load-then-present page at once. WhenAll is the one mutation that turns a strictly-faster
change into a hang; the pin refuses it by name.

One implementation on both sides: bridge.painted() (latched, double rAF) replaces a
per-shell one-liner, and the verb has ONE inbound home — onNavigatingGlobal -> a virtual
onPaintedSignal — with SingleChatPage's own branch deleted and replaced by an override
that still calls base. A second copy is how #251 and #288 MAJOR-1 both happened.
Mini-apps are excluded structurally: MiniAppPage is never pushed through pushPageLoaded,
so it has no gate to complete. The five DATA shells (chat-info, App details, tx detail,
Settings, Downloads) signal at the line their first real render finishes; settings signals
from rebuildHub and explicitly NOT from renderLayout, which runs once at boot with no
data. Placement is the correctness, and each of the five is pinned at its line by name.

Also: a temporary [CDPERF] chats stamp — the dispatcher's view of the ~60-row flush, to
pair with the shell probe's flush/done marks, bounded to the boot window. Retire with the
set.
