THE ROWS

L18  The logotype ink is a ROLE. One --text-logotype token: the brand primitive in
     light, neutral-01 in dark. Damir extended it to the desktop rail, which painted
     its own --icon-accent -- and one token can serve both with light unchanged to the
     pixel only because --primary-600 and --accent-600 are the same primitive. That
     equality is pinned; re-anchoring accent would move the rail's light mark silently.

L16  The splash squircle was ONE missing line. The light Android-12 theme declared no
     windowSplashScreenAnimatedIcon, so the system drew the LAUNCHER icon and painted
     its background layer inside the mask. A light drawable twin now exists, both
     drawables share one transform, the mark shrank ~20%, and the blue is #175595.
     ⚠ Damir's scope answer rested on a premise of mine that was FALSE:
     layout/splash_screen.xml is the window ground on EVERY api level (values/styles.xml
     sets it with no version qualifier), not "the pre-31 splash". Its gradient moved too.

L15  The flags were TEXT. The rows were built from a regional-indicator emoji pair, and
     Windows ships no colour flag glyph, so WebView2 drew the two letters -- a FONT, not
     logic. The row also existed TWICE because the LIST did: launch-shell.js carried a
     second copy whose own comment said "keep the two in sync BY HAND", and the welcome
     pill carried an emoji too.
     ★ I first replaced the emoji with drawn SVG. Damir rejected it and deleted the
     class: "do we keep the emojis on mobile right, as they are perfect." They are. The
     emoji now stays wherever the device can PAINT one -- tested on a canvas, because
     macOS has the glyphs and only Windows does not -- and the fallback is
     img/flags/*.png, thirteen PNGs shipping since the legacy build that nothing in the
     redesign referenced. He pointed at the folder. Only us.png was missing.
