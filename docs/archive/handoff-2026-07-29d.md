## ⚠ Build gotchas this session cost real time on — read before building

1. **Stale web assets.** MSBuild tracks the Raw-asset copy with a stamp in `obj`, so a changed
   `Spixi/Resources/Raw/html/*` can silently NOT reach the app bundle — you test last hour's
   HTML and conclude a fix failed. It bit us once and it very plausibly explains the earlier
   "#274 not fixed on first VM test" and the launch shells that "never got rebuilt".
   **Always verify after a build:**
   `grep -o "c-settings__qr svg { width: [0-9]*px" <app>/html/settings.html`
   To force it: `rm -rf Spixi/obj/Debug/<tfm> Spixi/bin/Debug/<tfm>` — deleting the bundle alone
   is NOT enough, the stamp survives.
2. **iOS device build** (Xcode 26.6 vs the SDK's pinned 26.5):
   `dotnet build Spixi/Spixi.csproj -f net10.0-ios -c Debug -p:RuntimeIdentifier=ios-arm64 -p:CodesignKey="Apple Development" -p:ValidateXcodeVersion=false`
   then the same with `-t:Run -p:_DeviceName=AI15`. `RuntimeIdentifier` is **not** optional
   (Debug iOS defaults to the SIMULATOR). After a clean, `-t:Run` needs a plain build first.
   `--launchdev` fails on every run — harmless, just tap the icon.
3. **Never `dotnet build` the solution on Mac** — `SPIXI.sln` drags in a Windows-targeting
   project (NETSDK1100). Always name `Spixi/Spixi.csproj`.
4. Phone must be **unlocked** for install (Auto-Lock → Never while working).

## ★ v1.0 SCOPE DECISION (Damir, 2026-07-29 — read before planning any work)

than assumed: most of what is gated off is *improvement over legacy*, not parity. Legacy
payment/app cards were already view-only (#179), legacy `addCall` was already lossy, and
reply/edit · retry · pin/mute persistence never existed in legacy at all. With the gates off
the app is at parity on the money paths and ahead nearly everywhere else — so shipping without
the cutover is a defensible product call, and it removes the dependency on the BE engineer's
calendar, which is the biggest scheduling risk.
