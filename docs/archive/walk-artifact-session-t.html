§1 The memory run — the reason for this walk

The app dies at 511 MB after ~30 minutes. This is the only open item that loses people's work. I found and fixed a real defect in the disposal code this session, but it does not change memory behaviour — so this run is what actually decides the cause.

The app now counts its own live WebViews and prints held=. That is the same number Android reports in the meminfo footer as WebViews:. Two independent measurements of one quantity is what makes this decisive.

Paste this once to define the snapshot helper:

$pkg = "com.ixilabs.spixi.dev"

function Snap($tag) {
  $f = "$env:USERPROFILE\Desktop\spixi-mem-$tag.txt"
  "=== $tag  $(Get-Date -Format o) ===" | Out-File $f -Encoding utf8
  "--- battery ---"                     | Out-File $f -Append -Encoding utf8
  & $adb shell dumpsys battery | Select-String "temperature|level" | Out-File $f -Append -Encoding utf8
  "--- meminfo ---"                     | Out-File $f -Append -Encoding utf8
  & $adb shell dumpsys meminfo $pkg     | Out-File $f -Append -Encoding utf8
  "--- MEMDIAG ---"                     | Out-File $f -Append -Encoding utf8
  & $adb logcat -d | Select-String "MEMDIAG" | Select-Object -Last 25 | Out-File $f -Append -Encoding utf8
  Write-Host "wrote $f"
  & $adb shell dumpsys meminfo $pkg | Select-String "TOTAL PSS|WebViews:|Views:|Activities:|AppContexts:"
}

T0 — launch the app, let it settle on the chats list, then:

⚠Rule out the heavy seed first. On a 10 × 1000 profile neither number means anything. And read the battery temperature in both files: end − start > 3 °C voids the capture — Session P's ladder was confounded by a phone that warmed 6 °C on the cable.

How to read it — held= in the MEMDIAG line against WebViews: in the meminfo footer:

what you seewhat it means
held= climbs and WebViews: climbs with itA WebView leak. skipped= then says how many disposals the on-stack guard passed over.
held= flat at 3–4, Native Heap or Graphics climbingNot WebViews. Stop looking at disposal — the growth is native or bitmaps.
the two disagreeMy instrument is wrong before the app is. Tell me; do not act on it.

If it is WebViews, this is the free next step — set CHAT_SPARE_ENABLED = false, rebuild, same half hour. Kills stop → the pre-warm is the cause and the fix is the disposal, not the flag.

§3 The disposal fix — and it is not a memory test

A page was marking itself “dead” every time anything opened on top of it, and never marking itself alive again. Three pieces of code read that flag as this page is gone. Two of them you can feel.

This changes no memory behaviour — it fixes guards that were firing on live pages.
