## The one thing that needs your judgement

**The `+` in a wallet password.** `HttpUtility.UrlDecode` form-decodes it to a space, so
the stored password is not the one the user typed. It is self-consistent inside the app —
every path decodes identically, so restore works — and changing the transport would lock
out every existing user whose password contains `+`. It is documented in
`docs/security-review-for-be-engineer.md` L2, which previously claimed a lockout that
does not happen. That row is corrected.

The residual is one test only you can run: create a wallet with password `a+b` in Spixi,
then open `wallet.ixi` in the Ixian desktop client with `a+b` and with `a b`. Ixian-Core
is not in this repo, so it cannot be settled from here.
