Message loss (#1155, #1160): a message Core had not written yet (its
delayed write, up to ~2 s) was dropped when a chat opened, because the
open re-reads the history from disk and replaces the in-memory list.

- New ArrivalGuard + CoreMessageWriter (Spixi only, Core unchanged):
  every added message marks its chat; before the re-read a marked chat
  is written first; after it, a message the read lost is put back.
- The window starts on a whole second, so a write can no longer delete
  older messages that arrived in the same second (a push backlog).
- Every push fetch and low memory write all marked chats at once; low
  memory keeps a chat with a message from the last 5 s.
- Deletes, my reactions and "sent" also mark the chat; removed contacts,
  cleared histories and wipes forget what was kept.
