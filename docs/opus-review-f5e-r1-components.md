## Verified OK — do not re-audit

Checked against the source, found sound. Listed so round 2 spends its budget elsewhere.

**The measurement (the brief's headline question).** `sheet.dataset.mAnchor = ''` lands at `desktop-anchors.js:114`, `sheet.style.width` at `:116`, and `offsetHeight` only at `:123` — so the `[data-m-anchor]` CSS IS applied when the height is read, and the width that drives the wrap is already inline. `openOverlay` appends synchronously (`overlay.js:106`), so the node is in the DOM and laid out. The base rule's interference is all out-specified at (0,4,0) vs (0,1,1): `max-width: var(--layout-content-max)` → `none`, `margin-inline: auto` → `margin: 0`, `transform: translateY(100%)` → `none`, and `padding-bottom: calc(16 + env(safe-area-inset-bottom))` → the flat shorthand (which is E-1 (ii)'s cause, but the override itself works). `box-sizing: border-box` is global (`base.css:33`), so the inline `width` includes the padding and the right clamp is honest. `offsetHeight` is a layout-box read — a transform could not distort it, and there is none at that moment anyway.

**z-order against #519 / #506②.** The sheet keeps `z-index: var(--z-44)` = 44 in both the anchored and the clamped-overlap case (the `[data-m-anchor]` rule touches no z-index), above the lifted row's `--z-42` and the scrim's `--z-40` (tokens.css:833-841). The chats-row menu cannot end up under anything: `.c-chatlist-item` carries `isolation: isolate` (`base.css:333-340`) but the sheet is a **body** child with a positive z-index, so the row's stacking context (z-index auto) paints beneath it regardless. The `::before` press layer at `z-index: -1` lives inside the row's own context and cannot escape it.

**a11y.** `anchorSheetToRow` only tags and inline-positions; `createSheet`/`openOverlay` still own `role=dialog`, `aria-modal`, the `aria-label` fallback, the Tab trap (`overlay.js:44-71`), `focusin` containment (`:75-80`), Esc (`:47-49`), scrim light-dismiss (`:102-104`) and focus restore (`:153-163`). The `html:root .c-sheet:not([data-open])` pointer-events rule (overlay.css:77-82) still covers both fade windows — the anchored sheet is `opacity: 0` before `[data-open]` and after it is dropped, and an opacity-0 element still hit-tests, so the rule is doing more work here than it did for the bottom sheet, not less. Exit still transitions `opacity`, so `transitionend` fires; the 400ms fallback (`overlay.js:185`) covers the rest.

**prefers-reduced-motion.** No guard is owed. `--duration-100/200/300` are all zeroed at `tokens.css:1138-1144`, so the anchored fade is instant — the same mechanism `[data-dt-anchor]` has relied on since #261. House rules are satisfied by the token, not by a per-rule media query.

**(c) is a real improvement, measured.** Washed ground vs unwashed, as a ratio: light chats list **1.233** (was 1.132), light chat canvas **1.232** (was 1.092), dark chats list **1.285** (was **1.011** — the old dark tint was effectively invisible), dark chat canvas **1.268** (was 1.022). The 5c-iii worry does not apply: the 10% hover step, not the 5% press step, is what landed here. E-4 is the only thing wrong with it.

**Swipe / selection / double-fire interplay.** `openChatRowMenu` calls `closeChatRowSwipe()` first (`chats-row-menu.js:36`) and the swipe transform is X-only (`chats-swipe.js:83`), so vertical placement is never read mid-spring; a horizontal residue would only shift the (clamped) left edge. `{ row, ...opts }` is safe at every call site — neither `chats-shell.js:271/284` nor chat.html's `menuOptsFor` puts a `row` key in `opts`, so the explicit row is never shadowed. Selection mode still short-circuits both gesture paths (`message-menu.js:183/206`), and the Android `contextmenu`-vs-timer guard (`:210`, `chats-row-menu.js:461`) is untouched.

**Containing-block arithmetic in production.** `host = document.body` in both shells (`chat.html:2071`, home.html's `document.body`); body is static with `margin: 0` (`base.css:37-39`) and `height: 100%`, so the abs-pos containing block is the ICB, its origin coincides with the body border box, and `rr.top − fr.top` is the correct coordinate whether or not the document is scrolled. `fr.width`/`fr.height` equal the viewport. The only place this breaks is N-8 (demo frames) and E-7 (iOS keyboard).

**F5-5 ①.** `setQrValue` defaults `quiet = 4` and offsets every module by it (`qr.js:2318-2327`), so the ISO quiet zone genuinely survives `padding: 0` — it is inside the viewBox, and `--surface-qr` shows through the transparent margin because the card keeps `.c-wallet-receive__qrcard`'s `background` (both classes are on the node, `wallet-receive.js:436`). The `.c-qr { width: 100% }` sizing rule is scoped to that same class, so it rides along. In light mode `--surface-qr` and `--surface-menu` are both `--neutral-10`, so dropping the hairline leaves only `--elevation-1` as an edge — that is the Account look Damir asked for, not a defect.

**F5-5 ②.** The persistent-thumb overrides out-specify the hover-only base: `:root[data-desktop] .c-addr-sheet.u-scroll` (0,4,0) beats `.u-scroll:hover` (0,2,0) and `.u-scroll::-webkit-scrollbar-thumb` (0,1,0) (`base.css:124-143`), both live inside the same `@media (hover: hover) and (pointer: fine)` block, and `.c-addr-sheet` really does carry `u-scroll` (`wallet-receive.js:426`). `scrollbar-width: thin` still comes from the base rule. Only the outer-clip tie (N-4) is fragile.

**F5-5 ③.** `--icon-info` on `--surface-neutral-02` = **8.71:1** light (`#004863` on `#edf0f2`) and **8.53:1** dark (`#8dbfd9` on `#161d28`). Comfortably AA at 20px. The `discGrad` import is gone with the disc (`wallet-receive.js:68`) and no other consumer in that file needs it.
