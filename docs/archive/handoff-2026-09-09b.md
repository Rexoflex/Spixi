## What the #835 retirement actually cost, for the next person

The deletion was the small half, exactly as #835 predicted. **Fifteen existing pins had their
subject removed**, including one that still `readFileSync`'d `chat-flow.js` and **would have
thrown and killed the whole suite from that point on**. Each was retired or re-based
deliberately, with the reason written where it stood — the invariant they guarded (no
stacking context on the chat canvas) is *not* retired, it is PIN-B's and is swept over the
whole cascade.

Two mechanisms worth carrying:

* **The extractor's `DYNAMIC` table is the authority for a dynamic key.** Retiring a style in
  the component changes nothing until that table changes too, and both i18n gates are blind
  to it by construction (they compare locales against each other). Its pin is DERIVED now.
* **A retirement is a FALL-THROUGH, never a migration.** The stored string is left alone and
  every reader normalises it — and there are **four** readers, not three: the #690 ladders
  plus the generated stylesheet's `:root`. GATE 62 asserts them as a set, and the jsdom block
  now *drives* it: a fixture storing `doodles` resolves to a selected matrix tile.

`device_bash` = a Linux VM with the repo mounted. **No `dotnet`, no `adb`, no tree-sitter**;
`cs-syntax-check` is skipped and the C# is unvalidated until Damir builds. `git --no-optional-locks`.

New this session:

* **`node --check` is weaker than the bundle's syntax gate.** It accepted a file with
  top-level `return` (Node parses `.js` as CommonJS, where the module wrapper allows it);
  `build-demo-bundle`'s ESM concat caught it. Use the bundle build as the authority.
* **source → bundle → shells.** Skipping `build-demo-bundle` silently tests the old code: a
  mutation appeared to SURVIVE a gate because only `build-shells` had been re-run.
* Harnesses must be sliced by **content**, not line number — three broke mid-session when
  earlier edits shifted the file.
