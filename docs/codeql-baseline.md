## What this scan cannot see
- **C# has no taint sources here.** A sanity query on the local database: 3,913 methods, 402 calls into `System.IO.File`,
  2 `Process.Start`, but **0 remote flow sources**. CodeQL's default (remote) threat model does not know a MAUI WebView
  message, a navigation URL, or an Ixian network message as a source, so the taint queries (path, command, XSS) have
  nothing to start from; only the non-taint queries (weak crypto, hard-coded secrets, …) can fire. 0 results is
  therefore NOT a proof that the bridge handlers are safe. The bridge gates, the isolation check and the gate diff
  cover that ground.
- **JS sources** are the browser ones: `location.search` is used by every shell (`?lang=`) and was tracked with no hit;
  data that C# pushes in through `executeUiCommand` / function arguments is not a modelled source.
- Ixian-Core (not in the repo; `Spixi.csproj` imports it from `../../Ixian-Core`): types unresolved, taint through it lost.
- The locally reported C# database quality: calls with a known target 80 % (threshold 85 %), expressions with a known
  type 92 %. Local NuGet restore was refused (the cloud proxy answers 403 for `api.nuget.org`), so the MAUI and NuGet
  types were missing; the SDK's .NET DLLs were used.

- CI restores NuGet packages from nuget.org (here: refused), so its C# database resolves more calls and MAY report
  results this run did not.
- CI scans the tree of the pushed commit, with the files this session adds (`scripts/quality/**`, the pins of
  `qtools`); this run scanned `ae7b8303` without them.
- The weekly `schedule:` does not run yet: GitHub runs it only from the workflow copy on the DEFAULT branch, and the
  default branch of Rexoflex/Spixi is `master`. Push / pull request to `redesign/frontend` run; a manual `workflow_dispatch` run also needs the file on `master` (GitHub's rule).
- `actions: read` is not granted (public repository; the codeql-action README asks only `security-events: write`, plus
  `contents: read` for a private one). If the first upload fails reading the workflow run, that permission is the fix.
