## 4 · ★★ THE RULES THIS SESSION PAID FOR

1. **`cp -al` IS NOT ISOLATION FOR A BUILD.** The hard-linked copies share inodes with
   the working tree, and `writeFileSync` truncates IN PLACE — so three parallel mutation
   builds wrote three different bundles into ONE file, and the main tree's built shells
   carried a MUTATED `home.html` until they were rebuilt. Rule 4's harness (`cp -al`,
   `os.remove` before writing) protects the SOURCE edit only. **Mutate in a full copy
   (`tar`), never a hard-linked one, and rebuild the main tree afterwards regardless.**
   A mutation that SURVIVED (M2, the tile-close) was this artefact, not a weak pin.
2. **`open(p,'w').write(open(p).read()…)` TRUNCATES THE FILE TO NOTHING.** Twice in one
   session, by the same hand: `smoke-test.mjs` (1.8 MB) and `settings.html`, both
   zeroed, both restored from git and every edit re-applied. Read into a variable, THEN
   open for write. Never nest the read inside the write.
3. **A HELPER IN A `new Function` STUB NEEDS EVERY FREE NAME.** `syncAttachAffordance`
   gained a call to `closeAttachTrayIfOpen`; the executed pin went red with
   "closeAttachTrayIfOpen is not defined" — the pin was right, the stub was stale.
4. **THE SAME GLYPH, TWO MEANINGS, IS FOUND BY A SWEEP, NOT BY LOOKING.** `arrow-up-right`
   had meant "send money" and "external link" for months. The P2 row nearly made
   `world` a third duplicate.
5. **MEASURE BEFORE ASSUMING — the baseline itself.** "110 files" was a partial tree;
   the arithmetic (141 − 30) found it in a minute.
