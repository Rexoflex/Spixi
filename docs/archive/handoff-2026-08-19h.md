## 2. What N71 actually is, in one paragraph

The two theme paths had drifted. The explicit Light/Dark pick PUSHED `setTheme` to a
hand-written list of WebViews and worked. The OS-follow path called
`reloadAllPages()` and rebuilt every document — and once #385/N66 made that path
reachable, the cost arrived with it: `home.html`'s Fix #8 sends `ixian:tab:tab1` on
every document boot, so an evening auto-switch threw the user back to Chats
(**N78**) and discarded unsaved input. A push creates no document, so **one change
closes both halves**, and **Fix #8 is untouched** — it is correct for the reload it
was written for. Both paths now run one shared enumerator,
`UIHelpers.getLiveShellPages(bool includeModal)`.

## 3. ★ What is now KNOWN that was not before

1. **The bare-global hazard is wider than the shells.** C# emits `setTheme` as a bare
   identifier, so any page the sweep reaches must define it. Thirteen shells did not.
   The **8 legacy pages** cannot define it at all — they carry the theme in a baked
   `<link href="css/*SL{SpixiThemeMode}">`, so the sweep is HYBRID: push where there
   is a handler, `reload()` where the theme is baked.
2. **★ `build-shells`' preflight cannot see an omitted destructure.** It validates the
   symbols a shell DOES destructure — its premise is staleness, not omission. A shell
   that calls a bundle export it never imported passes every existing gate. It
   happened **twice in one session in `chat.html`**, with two different symptoms: at
   module top level it kills the boot (blank conversation); inside a handler it boots
   fine and breaks only when that push arrives. Both are now gated structurally — a
   **destructure gate** over every shell, and a **jsdom boot gate** on the built chat
   shell.
3. **★ `applyPlatformPageChrome()` is not page-local on Android.** It calls
   `setEdgeToEdge`, which paints the ONE activity root view and the ONE window insets
   controller. Calling it per page in a sweep lets the LAST page decide the status-bar
   glyph colour. Use `applyPageSurfaceColor()` for a per-page refresh; re-assert the
   bars once, from the visible page, at the end.
4. **A "check nothing is missing" test passes vacuously when its input list is empty.**
   The new destructure gate has a self-check for exactly that, and the self-check
   fired on the first run.

## 6. Standing rules this batch re-earned

* **★ #395, again, three times over:** the mutation runs caught **three self-defeating
  pins** — a word-match a comment satisfied, a prefix match (`ignorePushedThemeX`
  satisfied `ignorePushedTheme`), and one whose mutation targeted the wrong site.
  Pin the SITE, and MUTATE it before believing it.
* **★ NEW: source-reading gates cannot see a throw.** Two of this batch's four MAJORs
  were found only by EXECUTING the built artifact. If a change can break a shell's
  boot or a push, run the shell.
* **★ NEW: a fix is not smaller than the thing it fixes.** The break-my-verdict round
  found that my own repair had regressed the #407–#410 bar work, and that a comment
  cleanup had silently reverted a migration I had already made.
* **★ #405, and it bit again:** renaming `PATTERN_LEVELS` changed nothing until the
  MANUAL table in `extract-strings.mjs` changed too — `strings[o.key]` is unextractable.
  Both i18n gates are blind by construction: they compare locales against **each
  other**, so a key missing from all of them is perfectly "consistent". The note
  recording this exact trap was three lines above the code I had to edit.
* **★ #410:** since full bleed, anything derived from "the current surface" must be
  READ, not REMEMBERED. `settings.html`'s Auto resolution was a `const`.
* Verify at source (#215) · never build past a missing repro (#294) · bundle BEFORE
  shells · DECISIONS rows at decision time · the security handover gate while building
  · #383 a green smoke run does not prove the generators work · #387 a red row can be a
  dirty build · `git --no-optional-locks` always.
