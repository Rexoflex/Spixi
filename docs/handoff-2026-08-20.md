## 3. ★ What is now KNOWN that was not before

1. **★ Moving chat onto `chatStream` wholesale would have broken deployed peers, silently
   and in the worst direction.** The code landed AFTER `spixi-0.9.19`; an older peer has no
   case for it, and its `requireRcvConfirmation` switch has a `default:` arm that sends the
   receipt anyway. The message vanishes on the receiver and the SENDER shows a delivered
   tick. In a group whose owner is older, the room goes silent. **The message code must be
   chosen per message** — that is now the one open QUESTION in the cutover doc, alongside
   the alternative of a capability bit (bit 64 is free).
2. **`ChatStreamMessage` measured its size in characters when written and in UTF-8 bytes
   when read.** A long non-ASCII body passed every sender check and threw inside the
   receiver's parser. Latent until this batch used the path.
3. **#229's load-then-present bought the lock's flicker fix with a content exposure**, and
   nobody wrote the price down. That is #438 in one sentence.
4. **An Ixian txid is not hex.** `getTxIdString()` returns `"<blockHeight>-<Base58>"`. The
   first cut's guard refused every real id — and the smoke pin blessed the regex as if it
   were the fix, which is the "green pin over a dead feature" shape.
5. **A fully synced client reports `target = current + 1` about once every 30 seconds**,
   because the network height is extrapolated from the last block's timestamp. Any progress
   UI built on `current >= target` will flap.
6. **★ Three of the six MAJORs were in the FIXES, not in the build** (#446). The hysteresis
   was keyed on visibility, which the indeterminate state un-hides; the uncover guard
   stranded a shield; and the ModalStack walk painted the shield over the LockPage itself.
