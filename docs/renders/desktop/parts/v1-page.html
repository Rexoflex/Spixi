What v1 desktop can add now

Four small changes that make v1 desktop feel less like a phone port, without new risk. Each frame pair shows today's v1 desktop and the same window with the change. The frames are drawn with the real tokens.css and the real icon set, at 1440 × 900, with Windows 11 and macOS chrome. Use the bar to switch light and dark.

Today, and v1 with all four

The whole window, before and after. The chat area does not change: it stays in its own WebView, with the same header, bubbles and composer.

1

Native title bar · Windows

How MAUI Window.TitleBarBridge 1 new push: setChatFilter(text)Page verbs noneEffort ~1 session

The bar shows the Spixi icon and name and a centred "Search chats" box. The box is a native field; typing pushes the text to the home shell, which runs the filter it has today. Ctrl K focuses it from anywhere, also from inside the chat. The colours come from the tokens, so the bar follows light and dark. The list's own search field goes away on Windows.

2

Use the title strip · macOS

How CSS in home.html and chat.htmlBridge none (the --safe-top push exists)Check first drag and clicks in the stripEffort 0.5–1 session

Today every shell pads below the title strip, so an empty band runs across the top of the window. With the change, the window buttons sit at the top of the rail and the list and chat headers sit in the band, as Mail and Messages do. The list keeps its own search field (Mac pattern). Before the work, check on a Mac that the window still drags from the band and that a click on an HTML button in the band reaches the page.

3

Chat list polish · both

How chatlist-item.css under :root[data-desktop] + the chats listBridge none (row-menu actions)Page verbs noneEffort ~1 session

"Pinned" and "Chats" headers with counts, which fold. Rounded, inset shapes for the selected and the hovered row. On hover, four buttons on the row: pin, mute, chat info and more. They call the same actions as the row menu, so no new verb. The mobile list does not change.

4

Second-device warning · both

How C# reads our own presence entriesBridge none (existing showWarning)Also on mobileEffort 0.5–1 session

When the same account is live on another device, new messages can go to that device instead of this one. C# sees this in our own presence entries (one per device) and shows the existing home banner with a fixed text. The user can close it. It goes away when the other device is quiet for some minutes. This is the v1 step from the multi-device note; real multi-device sync stays a Core topic.
