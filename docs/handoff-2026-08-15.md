## ⚠ W2 case A was BUILT, then REVERTED after the audit — the rail is still covered

You approved unverified C# for the desktop-rail fix. I built it, the #46 adversarial
pass took it apart, and I reverted it. Full reasoning in DECISIONS #338. Short version:

- `popPageAsync()` means two different things. In the push world it pops the *top of
  the stack*; in the overlay world it is identity-aware and closes *the caller's own
  overlay*. Every converted page therefore tore down the wrong screen — Wallet → Send →
  pick recipient → tap a contact **destroyed the Send page and left the recipient list
  up**, with the payment uncompletable.
- `WalletSentPage.onDismiss` indexes `NavigationStack[Count-2]`; on a detached proxy
  that stack is empty → `ArgumentOutOfRangeException` **on the UI thread**, raised
  inside the WebView `Navigating` handler. Dismiss after sending money would throw.
- The `legacyStageTimeoutMs = 400` failsafe rested on a false premise. Those legacy
  pages **do** emit `ixian:onload` (`<body onload="onload()">` → `js/spixi.js:88`), so
  400 ms was a race against WebView2 boot, not a safety net.
- And it wouldn't have delivered the feature anyway: the `ixian:tab:` sweep closes only
  settings / contact-details / formpane / txdetail overlays, so a staged wallet page
  would have left the rail **visible but inert** — arguably worse than covered.

Every C# file involved is now byte-identical to the pre-batch tree. **W2 case A is
still open.** A correct fix has to make each converted page's pop path overlay-aware
and extend the tab sweep *first*; that is a design task, not a patch. Case B (the
takeover insets) and `--layout-rail-width` were already shipped in the #337 tree and
are untouched.

## Apps perf — what I fixed, and the two causes I couldn't

Fixed (FE, verified in real Chromium with 5 × 240 KB icons): `renderAppsList` rebuilt
every row on every render — a new `<img>` per row meant a fresh decode of a ~240 KB
`data:` icon each time. Rows are now keyed by app id with field-wise reuse and an
in-place reconcile; the cache survives the mid-burst empty render. **First push adds 15
nodes; six identical re-pushes add 0.** Smoke asserts the `<img>` creation count.

Not fixed — both need you, both are real:

- `Spixi/Utils/Utils.cs:38` `escapeHtmlParameter` **base64-encodes the already-base64
  icon a second time**: 240 KB → 320 KB per icon, per push.
- `src/bridge/native.js:34` decodes with
  `Uint8Array.from(bin, c => c.codePointAt(0))` — measured **19.6 ms vs 1.0 ms** for a
  plain index loop. ~20× on a 3-line change.
- `loadApps(true)` bypasses the `shouldRefreshApps` gate on every entry to tab 3, so
  C# re-pushes `clearApps + addApp×N` on **every tab switch**. The FE reconcile now
  absorbs this, but the marshalling cost is still paid every time.

## The #46 audit found real bugs — these were fixed, not just noted

Three disjoint auditors ran over the batch. Beyond the W2 revert:

- **A money bug.** W6 wired Enter-in-the-contact-search to "send to the first enabled
  contact". With an empty query that fires a real request at the first contact in your
  roster, no confirm, and a soft keyboard's Go key triggers it too. Removed; sending is
  an explicit tap on a named row. The spec said "same for Enter-to-send *if* the search
  field supports it" — permission to extend an existing path, not to mint one.
- **A leak.** The Chat-appearance preview mounts a live rAF loop + ResizeObserver +
  document listener, and nothing detached it. `renderLayout()` replaces the screen's
  children on Back, on `setLocale`, on `setPaneMode`, on `onRepresented` — so every
  visit leaked another loop against a detached node, and in pane mode they stacked
  without navigating at all. Now released alongside `releaseDownloads` (#267).
- **Empty states flashing during load** (see F5 item 5) — the shells built their lists
  synchronously with an empty model. Gated: chats on the real `clearChatsDone` verb,
  apps/wallet on a 400 ms quiet window (no new bridge verb). Measured: 0 frames showing
  a zero state during a burst; a genuinely empty surface still gets there in ~430 ms.
- **A lost i18n update.** Concurrent edits dropped three of my `en-us.json` keys, which
  silently made the pattern-style labels un-translatable in all 8 locales (that file is
  the key universe for `build-locales`). Restored and re-verified: all 7 locales rebuild
  byte-identically from source.
- Plus: duplicate app ids collapsing to one row, an 806 KB banner fetched at boot, a
  double stylesheet link, a Russian label overflowing at 320 px, and radiogroup a11y.
