Session Q (#804) — the Account sublevels stop booting a WebView

Backup, Downloads and Change password were the only Account rows that pushed a
new C# page, and every one of those pages carries its own WebView. #803 measured
the cost on Android: one minute of Account -> Backup/Password/Download on a
BRAND-NEW account with zero chats read 12.19 % janky frames, 99th 48 ms, with the
GPU idle at 11 ms throughout. On the heavy-seed profile, at one temperature, the
same minute read 21.66 % while scrolling 50 conversations and opening three read
4.09 %. The data was never the problem; three cold Chromium boots on the main
thread were.

The fix is `paneMode && ` deleted from three guards in src/shells/settings.html.
Nothing else changed behaviour. The screens, the capabilities and the verbs all
already existed and already shipped on desktop since #243 / #267 / #341; the
capability flags were being pushed to the phone the whole time
(SettingsPage.onLoad builds and pushes `caps` outside its `if (paneMode)` block,
and always has). Only the shell refused to use them.

One thing the first draft claimed and the review disproved: desktop is NOT
unchanged. A WinUI or Mac window below the pane breakpoint has no data-pane, so
it pushed the pages too and now renders them inline — one fewer WebView boot
there as well, in the grammar About and How-to-use already use. Rendered,
checked, and walked (rows C3b / C3c).

  1. the three screens render correctly at mobile width — booted from file:// in
     Chromium at 432x900 @2.5 with an Android UA, driven through the real
     executeUiCommand wire, rendered beside the standalone shells they replace
     (docs/sheets/session-q/)
  2. renderLayout's non-pane branch builds any view generically
  3. back — hardware back included — is view-agnostic and returns to the hub
  4. all three caps are pushed on every form factor
  5. security: cancel-first navigation, no URL in any log, the shell scrubs its
     password fields on every leave path incl. the park route
  6. nothing is retired — BackupPage is still reached by the backup nudge through
     HomePage's own branch

the app still pays for happen earlier. This removes the boot.
