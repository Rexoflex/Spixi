## 3 · The render harness (rebuilt this session — better than J's)

`/tmp/j/render/harness.mjs` — Playwright (`playwright-core`, npm) over
`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`, `--allow-file-access-from-files`. It
boots the BUILT shell (`Spixi/Resources/Raw/html/<shell>.html`) from `file://` exactly as the
device does, 432×900 @ 2.5, an Android UA (`isMobile`, `hasTouch`), Roboto forced via an
init-script `<style>` (apt `fonts-roboto`), theme via `colorScheme` + `data-theme`. A setup
module drives the page through `executeUiCommand(window[name], ...base64 args)` — the same
wire C# uses — so every render is the real shell with real pushes (`setup-group.mjs`:
onChatScreenReady → setChatMode → updateGroupChatNicks → clearMessages → addThem/addMe ×7 →
onChatScreenLoaded; `setup-apps-menu.mjs`: selectTab tab3 → clearApps/addApp ×7/clearAppsDone →
click a ⋯). `page.evaluate` for measurements (getBoundingClientRect). PNG out; PIL for sheets.
Symlink `node_modules` into the harness dir. Keep `page.on('pageerror')` — a shell that throws
renders a spinner and looks like a layout bug.
