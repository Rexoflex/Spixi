## 2. What N66 actually was — read before you touch theming again

`App.xaml.cs` pinned `Current.UserAppTheme` to a concrete value at boot, and the
OS-flip handler pinned it again as its own first line. MAUI resolves
`Application.RequestedTheme` to `UserAppTheme` whenever that is not
`Unspecified`, and it drops the `RequestedThemeChanged` event when the resolved
value does not change. **The handler therefore disabled itself the first time it
ran**, and everything it does — the `SpixiThemeName` re-bake, `setEdgeToEdge`,
`reloadAllPages`, and with it the #315 parked-Account dispose — has been dead
since the boot event.

`UserAppTheme` now stays `Unspecified` for the whole session, `ThemeManager`
resolves "automatic" from the platform theme (`isPlatformDark()`), and the
revived handler returns early unless the appearance is System.

★ **Honest residual — RESOLVED by the F5, kept for the record.** This explains the Windows sibling (panes disagree) and a
System flip doing nothing. It does **not** by itself explain the Android report
that the Account screen stays light while the rest of the app is dark: no
stylesheet carries `prefers-color-scheme`, so no shell reacts to a live OS flip
at all. **A4 PASSED on device**, so the dead event was the whole
mechanism on both platforms. The Account-stays-light symptom that remains is a
DIFFERENT defect with a different mechanism — see N71.
