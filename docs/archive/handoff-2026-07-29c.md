## The F5 round (#289) — the interesting one

Damir: *"narrow window, hidden balance, open detail, click Show amounts → doesn't show amounts."*

**It was not about window width.** `checkTransaction()` pushes `clearEntries` as its **first**
statement (`WalletSentPage.xaml.cs:121`) and then early-returns when the activity status is
unchanged (`:129-133`), pushing no `addEntry` and no `setData`. `updateScreen()` polls it at 1 Hz
for as long as `!isConfirmedDisplayed`, which is only ever set for an `ActivityStatus.Final`
transaction (`:137`). So on any **pending/unknown** tx the shell's entry buffer is empty a second
after open, while the painted card still shows the last good burst.

That was safe while `setData` was `render()`'s only caller. #285's per-view reveal added a second
caller → revealing rebuilt the card from `{}`: chrome intact, no money in it. A **confirmed** tx
stops polling and reveals fine, which is exactly why it looked narrow-only.

**Fix:** a staging buffer. `clearEntries` / `setReceivedMode` / `addEntry` write to `staging`;
`setData` commits into `model` and renders. `render()` is now idempotent for every caller, and the
long-documented *"buffer reset only — never clears the rendered card"* contract finally holds for
re-renders too.

Proven with a jsdom harness against the **built** shell — the pre-fix build fails 5 assertions
exactly as reported, the post-fix build is **13/13**. The harness is throwaway (it lived in
`_to_delete/`); the durable guard is the smoke assertion.

**Audit of the fix: 0 BREAKS**, diagnosis confirmed at file:line, plus three things worth knowing:
- **R1 (fixed):** the reveal eye was offered during the fail-closed *unknown* window, and the
  first `setHideBalance` push unconditionally clears `revealed` — so a tap in that sub-millisecond
  window was silently undone. The eye now waits for the flag (`canReveal()`).
- **R10 (fixed):** the mask predicate was inline at two call sites; now one `isMasked()`.
- **Audit correction:** the "a received payment's `+` flipped to `-`" symptom I originally wrote
  into the comment is **not observable** — an empty entry renders no amount, so no sign is emitted.
  Recognise a recurrence by the **blank card**, not by a wrong sign. Comment corrected.
